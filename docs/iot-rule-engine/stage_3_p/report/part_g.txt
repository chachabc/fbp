================================================================
Part G — 통합 시나리오
================================================================

[ 스펙 요구사항 ]

1. 로컬/브릿지 혼합 환경에서 전체 시스템 정상 동작 확인
2. 동적 플로우 변경이 무중단으로 적용됨을 확인
3. 모든 통계가 InfluxDB에 누적되며 Grafana 등에서 조회 가능함을 확인
4. CLI를 통한 전체 운영 시나리오 시연

스펙 시나리오 구성:
  Flow-1 (MQTT 브릿지): smart-building
    MqttSubscriber → ThresholdFilterNode → AlertNode / LogNode
  Flow-2 (로컬): health-check
    TimerNode → CounterNode → LogNode

----------------------------------------------------------------
[ 환경 구성 ]

Docker Compose로 4개 서비스를 실행한다.

== docker/docker-compose.yml ==

services:
  mqtt-data-broker:          # IoT 센서 데이터 수집용 (1883)
    image: eclipse-mosquitto:2.0
    container_name: fbp-data-broker
    ports: ["1883:1883"]

  mqtt-system-broker:        # FBP 엔진 내부 노드 간 메시지 전달용 (1884)
    image: eclipse-mosquitto:2.0
    container_name: fbp-system-broker
    ports: ["1884:1883"]

  influxdb:                  # 시계열 메트릭/도메인 통계 저장 (8086)
    image: influxdb:2.7
    container_name: fbp-influxdb
    ports: ["8086:8086"]
    environment:
      DOCKER_INFLUXDB_INIT_ORG:    fbp
      DOCKER_INFLUXDB_INIT_BUCKET: fbp-metrics
      DOCKER_INFLUXDB_INIT_ADMIN_TOKEN: fbp-admin-token-please-change
      DOCKER_INFLUXDB_INIT_RETENTION:   30d

  grafana:                   # InfluxDB 시계열 데이터 시각화 (3000)
    image: grafana/grafana:10.4.0
    container_name: fbp-grafana
    ports: ["3000:3000"]
    volumes:
      - ./grafana/provisioning:/etc/grafana/provisioning
      - ./grafana/dashboards:/var/lib/grafana/dashboards

실행:
  cd docker && docker compose up -d

접속:
  InfluxDB UI: http://localhost:8086  (admin / admin12345)
  Grafana:     http://localhost:3000  (admin / admin)

[ 플로우 정의 파일 ]

== flows/health-check.json (로컬 플로우) ==

{
  "id": "health-check",
  "transport": { "type": "local" },
  "nodes": [
    {"id": "timer",   "type": "TimerNode",   "config": {"intervalMs": 5000}},
    {"id": "counter", "type": "CounterNode", "config": {}},
    {"id": "logger",  "type": "LogNode",     "config": {}}
  ],
  "connections": [
    {"from": "timer:out",   "to": "counter:in"},
    {"from": "counter:out", "to": "logger:in"}
  ]
}

역할: 5초마다 TimerNode가 트리거 → CounterNode가 카운트 누적 →
     LogNode가 로그 출력. 엔진이 살아있는지 확인하는 헬스체크 플로우.

== flows/smart-building.json (MQTT 브릿지 플로우) ==

{
  "id": "smart-building",
  "transport": {
    "type": "mqtt",
    "broker": "tcp://localhost:1884",   ← 시스템 브로커 (노드 간 FBP 메시지)
    "qos": 1
  },
  "metrics": {
    "domain": [
      {
        "name": "temperature",
        "source": { "node": "temp-sensor", "port": "out" },
        "field": "value",
        "windows": ["1m", "1h", "1d"]
      }
    ]
  },
  "nodes": [
    {
      "id": "temp-sensor",
      "type": "MqttSubscriberNode",
      "config": {
        "brokerUrl": "tcp://localhost:1883",  ← 데이터 브로커 (IoT 센서 데이터)
        "topic":     "sensor/temp",
        "qos":       1
      }
    },
    {"id": "temp-rule",   "type": "ThresholdFilterNode",
     "config": {"fieldName": "value", "threshold": 30.0}},
    {"id": "alert",       "type": "AlertNode",  "config": {}},
    {"id": "normal-log",  "type": "LogNode",    "config": {}}
  ],
  "connections": [
    {"from": "temp-sensor:out", "to": "temp-rule:in"    },
    {"from": "temp-rule:alert", "to": "alert:in"        },
    {"from": "temp-rule:normal","to": "normal-log:in"   }
  ]
}

역할: 데이터 브로커(1883)의 sensor/temp 토픽에서 온도 데이터를 수신
     → 30도 초과 시 AlertNode 발동, 이하는 LogNode 출력.
     노드 간 메시지는 시스템 브로커(1884)를 경유.

== flows/temp-sensor-local.json (TemperatureSensorNode 기반 로컬 플로우) ==

{
  "id": "temp-sensor-local",
  "transport": { "type": "local" },
  "metrics": {
    "domain": [
      {
        "name": "temperature",
        "source": { "node": "sensor", "port": "out" },
        "field": "temperature",   ← TemperatureSensorNode payload 필드명
        "windows": ["1m", "1h"]
      }
    ]
  },
  "nodes": [
    {"id": "timer",     "type": "TimerNode",
     "config": {"intervalMs": 2000}},
    {"id": "sensor",    "type": "TemperatureSensorNode",
     "config": {"min": 20.0, "max": 40.0}},
    {"id": "temp-rule", "type": "ThresholdFilterNode",
     "config": {"fieldName": "temperature", "threshold": 30.0}},
    {"id": "alert",     "type": "AlertNode",  "config": {}},
    {"id": "normal-log","type": "LogNode",    "config": {}}
  ],
  "connections": [
    {"from": "timer:out",      "to": "sensor:trigger"},
    {"from": "sensor:out",     "to": "temp-rule:in"  },
    {"from": "temp-rule:alert","to": "alert:in"      },
    {"from": "temp-rule:normal","to": "normal-log:in"}
  ]
}

역할: 2초마다 내부적으로 랜덤 온도를 생성(20-40°C)하여 임계값(30°C) 기준으로
     경보/정상 로그를 출력. MQTT 없이 순수 Java로 온도 데이터를 생성하므로
     docker 없이도 InfluxDB 메트릭을 확인할 수 있다.

[ Grafana 대시보드 확인 ]

http://localhost:3000 → FBP Engine 대시보드

패널 구성:
  1. Node — Messages In/Out:  노드별 in_count/out_count 시계열 차트
  2. Node — Avg Processing Time: 노드별 avg_time_ms 시계열 차트
  3. Wire — Delivered Messages:  와이어별 delivered 카운트
  4. Wire — Queue Size:         와이어별 queue_size 게이지
  5. Sensor — Temperature (1m avg): sensor_stats_1m의 avg/min/max

Grafana 프로비저닝:
  - datasource: influxdb.yml (uid=influxdb-fbp, Flux 모드)
  - dashboard:  fbp-engine.json (파일 기반 자동 등록)
  주의: 파일 프로비저닝에서 ${DS_INFLUXDB-FBP}는 해석되지 않으므로
        datasource 참조를 uid 문자열 "influxdb-fbp"로 하드코딩

[ 발견 및 수정한 주요 문제들 ]

1. TemperatureSensorNode payload 필드명 불일치
   문제: ThresholdFilterNode config에 fieldName: "value"로 설정했으나
         TemperatureSensorNode는 payload에 "temperature" 키를 사용.
   수정: fieldName과 domain metrics field를 "temperature"로 변경.

2. MQTT keepAlive 타임아웃
   문제: 유휴 와이어(메시지 없는 시간이 60초 초과)에서
         "Timed out as no activity" 오류 발생 후 연결 끊김.
   수정: MqttConnectionOptions.setKeepAliveInterval(300) — 5분으로 연장.

3. MetricsCollector tick 로그가 CLI 프롬프트 간섭
   문제: AbstractNode.process()의 System.out.println이 콘솔 출력.
   수정: log.debug로 변경 + logback.xml로 모든 로그를 파일로만 출력.

4. MetricsCollector written: 0
   문제: FlowManager가 단일 인자 생성자로 생성되어 metricsCollector=null.
   수정: Main.java에서 MetricsCollector 먼저 생성 후
         new FlowManager(registry, metricsCollector)로 전달.

5. InfluxDB "organization not found"
   문제: 구 org(iot-lab) 자격증명 사용.
   수정: buildInfluxConfig()에서 기본값을 fbp/fbp-admin-token-please-change로 통일.

6. Grafana datasource not found
   문제: dashboard JSON에 ${DS_INFLUXDB-FBP} 변수를 사용했으나
         파일 프로비저닝에서는 변수 치환이 지원되지 않음.
   수정: datasource.yml에 uid: influxdb-fbp 명시,
         dashboard JSON 전체에서 "${DS_INFLUXDB-FBP}" → "influxdb-fbp"로 교체.
